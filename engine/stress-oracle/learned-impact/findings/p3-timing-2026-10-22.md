# P3: timing P2's trained model through the Slang port (2026-10-22)

The planning session asked for real numbers for the trained model's Slang port, on Metal and
in Chrome WebGPU, then with the lossless levers applied. The workloads:
- one M5 free-wall call;
- the wall row;
- batches of 1, 5, 20 and 50 islands of about 220 chunks;
- one island of about 10k chunks.

All runs were in one quiet GPU window: P2's MPS job was paused, P3 was asked to hold GPU
tests, and P1 records on the CPU. One perf job ran at a time.

**Machine:** Apple M3 Max.
- Metal: the Metal library path.
- Chrome: the in-app Chromium, WebGPU through Tint, with timestamp queries.

**Model:** P2's `sweep-all3` export (W32, rounds 2/1/2/1/2, 2 BSMS levels, variant B, 4 edge
types). The bulk-v1 retrain has the same architecture, so the same cost; its export was not
written yet.

## Method

- **Program:** `stress_learned::outcome_program::compile_batch` compiles the calls into
  one op program in P3's layout: every call's chunks, then every call's impactors.
- **Kernels:** `stress-gpu/shaders/outcome_gnn.slang` runs the program.
- **Tools:**
  - native: `outcome_gnn_bench` (stress-rubble example);
  - browser: `web-probe/outcome.html` over stress-web's `outcome_gnn_*` exports, running the
    same compiled programs (OGNN1 files).
- **Correctness first:** `--check` compares every program's GPU outputs with the CPU
  interpreter. Every workload and variant agreed to 0.8–3.1e-6 (relative). The CPU
  interpreter itself matches the PyTorch-checked reference.
- **Metrics:**
  - **steady**: 30 forward passes in one submission, wall time ÷ 30. This is the number to
    use: a busy GPU, as consecutive frames keep it;
  - **gpu**: the pass's timestamps per isolated submit. On Metal these vary 3–10× between
    repeats, because the GPU clocks down between isolated submits. In Chrome they agree with
    steady;
  - 20 warm-up passes, 30 timed.
- **Real calls:**
  - the M5 calls come from `learned_impact_outcome_calls` on P1's parity records;
  - the batches use 50 distinct ~220-chunk contact calls from P1's validation set;
  - the 10k island is synthetic: a 40×25×10 bonded grid, 28,350 bonds, with feature rows
    cycled from the M5 call. Its values aren't physical; its shape is.

## The network call alone (steady, ms per call)

| Workload | chunks | Metal base | Metal best | Chrome base | Chrome best |
|---|---|---|---|---|---|
| M5 free wall | 220 | 1.79 | 1.84 | 1.33 | 1.52 |
| M5 wall row | 440 | 1.99 | 2.02 | 1.61 | 1.84 |
| 1 × 220 | 220 | 1.79 | 1.84 | 1.33 | 1.52 |
| 5 × 220 | 1,100 | 2.23 | 2.10 | 2.14 | 2.04 |
| 20 × 220 | 4,552 | 4.64 | 2.57 | 6.08 | 2.86 |
| 50 × 220 | 11,328 | 9.57 | 3.89 | 13.16 | 4.33 |
| 1 island | 10,000 | 11.80 | 4.76 | 16.09 | 5.20 |

The columns:
- **base**: the straightforward kernels;
- **best**: tiled MLPs, fused edge sums, the node-projection lever where it pays, and the
  two-stage mean, which every variant has;
- the best column takes, per row, the faster of lever on and lever off;
- full matrix: `p3-timing-data/`.

- **Small calls are latency-bound, not compute-bound.** A 220- or 440-chunk call costs
  1.3–2.0 ms whatever the kernels, with 56–80 dependent dispatches (about 25 µs each). So
  every island of a frame belongs in one batch: 20 islands cost 2.6 ms (0.13 ms each), 50
  islands 3.9 ms.
- **For small calls the levers are neutral or slightly negative.** The tiled kernel's tiles
  are mostly empty below 256 rows; it is used only from 256 rows on. The lever adds
  projection dispatches.

## The levers, measured (all lossless: the same arithmetic, reassociated sums)

1. **Two-stage per-call mean.**
   - The global node's mean over a 10k-chunk island was one CSR row walking 10,000 rows,
     nine times per pass.
   - Splitting it into blocks of 256, then the blocks, took the island from 15.7 to 4.6 ms on
     Metal (tiled + fused + lever).
   - Every variant above has it.
2. **Tiled MLP** (`gnn_mlp_tiled`: GEMM tiles of 64 rows × 32 channels, 4×4 per thread,
   from the P0 probe):
   - 50×220: 9.6 → 4.2 ms (Metal), 13.2 → 4.7 ms (Chrome);
   - 10k island: 11.8 → 5.3 ms (Metal), 16.1 → 6.0 ms (Chrome).
3. **Fused edge sums** (`SEG_CSR`: each node MLP stages its incoming-edge sums itself):
   - 12 fewer dispatches (68 → 56);
   - about 0.05 ms on small calls;
   - lost in the noise on large ones.
4. **Node-projection lever** (`W_s·h`, `W_d·h` once per node, used only for edge types with
   more edges than nodes):
   - 10k island: 5.34 → 4.76 ms (Metal), 5.98 → 5.20 ms (Chrome);
   - 50×220: 4.20 → 3.89 ms;
   - neutral on small calls.
   - The first version projected for every edge type, including 2-edge impactor contacts,
     and was a loss on large graphs; per-type selection fixed that.

**Not done:**
- **Fusing whole rounds** (edge MLP plus sum plus node MLP in one dispatch), which would
  cut the small-call latency floor.
- **f16 storage.** It is lossy, so it needs the user's decision.
- **Moving the per-call table build to the GPU.** Today the host compiles each call in
  1 ms (220 chunks) to 30 ms (10k), which P3's single-submission frame can't afford for large
  islands.

## Per-frame baselines (Metal, `learned_p0 gpu`, frame totals: rubble engine plus stress)

| Scene | blast_parity | punch | impact frames (punch) |
|---|---|---|---|
| free_wall_late2 (wall_ram_late2) | 2.10 ms median | 2.49 ms median | 3.0–3.8 ms |
| wall_row_late2 (wall_row2_late2) | 11.04 ms median (31.6 ms peak) | 3.16 ms median | 3.7–6.2 ms |

Frames 0–2 include first-use pipeline creation (up to 47 ms) and are excluded from the
medians. Run as P0's GPU baselines: `--seconds 0.5`, `STRESS_GPU_FIXED_HORIZON=1`; punch
= `blast_parity_routed` with `STRESS_IMPACT_PUNCH=gpu`.

**The full learned path per frame** (features, network, decode, apply) needs P3's GPU
feature assembly, which isn't built yet. P3 is asked for its stub-network path per frame on
both scenes. The learned frame is then that plus the network call above:
- one call per impact frame;
- about 1.5–1.9 ms for these 220–440-chunk islands.

## Reproduce

```
cargo build --release -p stress-rubble --features gpu --example outcome_gnn_bench
LEARNED_IMPACT_P3_BATCH=runs/p3-bench/batch_220.txt target-p0/release/examples/outcome_gnn_bench --export <export> [--tiled --fused] --check --warmup 20 --repeats 30
outcome_gnn_bench ... --write-programs runs/p3-bench/programs --write-only   # for the page
wasm-pack build stress-oracle/crates/stress-web --release --target web --out-dir ../../learned-impact/runs/web-probe-pkg --no-typescript
# serve engine/ and open /stress-oracle/learned-impact/web-probe/outcome.html?programs=...
```
